2a. MATCHING DEL FIN DE SEMANA (1a16ef5)
-----------------------------------------

Fragmento crudo de sitport-routes.js en 1a16ef5:

    const MAX_DIST_KM = 80;
    const matched = [];
    const vistas = new Set();

    for (let pi = 0; pi < ruta_puntos.length; pi++) {
      const punto = ruta_puntos[pi];
      if (!punto || punto.lat == null || punto.lng == null) continue;

      let mejorId = null;
      let mejorDist = Infinity;
      for (const [id, c] of Object.entries(BAHIA_COORDS)) {
        const d = distKm(punto.lat, punto.lng, c.lat, c.lng);
        if (d < mejorDist && d < MAX_DIST_KM) {
          mejorDist = d;
          mejorId = Number(id);
        }
      }

      if (mejorId != null && !vistas.has(mejorId)) {
        vistas.add(mejorId);
        matched.push({ idBahia: mejorId, coords: BAHIA_COORDS[mejorId], rutaIdx: pi });
      }
    }

    const excluidas = new Set();
    if (matched.length > 0) {
      excluidas.add(matched[0].idBahia);
      excluidas.add(matched[matched.length - 1].idBahia);
    }
    if (zarpe_id != null) excluidas.add(Number(zarpe_id));
    if (recalada_id != null) excluidas.add(Number(recalada_id));

    const restricciones = await sitportService.consultaRestricciones();
    const porBahia = new Map();
    for (const r of restricciones) {
      if (r.bahia == null) continue;
      if (!porBahia.has(r.bahia)) porBahia.set(r.bahia, []);
      porBahia.get(r.bahia).push(r);
    }

MECANISMO:
  1. Para cada waypoint, calcula haversine a los 163 puntos de BAHIA_COORDS
  2. Guarda la bahia mas cercana SI esta dentro de MAX_DIST_KM (80 km)
  3. Deduplica por Set (una bahia no se agrega dos veces)
  4. Excluye primer y ultimo match como zarpe/recalada
  5. Busca restricciones SITPORT para las bahias matcheadas

PROPIEDADES CLAVE:
  - Distancia MAXIMA de 80 km: ningun waypoint matchea una bahia cuyo
    punto central este a mas de 80 km
  - Sin Voronoi: el matching es punto-a-punto, no poligono
  - Sin PostGIS: calculo puro en JavaScript (haversine)
  - El radio de 80 km actua como CAP DURO: agua abierta a >80 km de
    cualquier bahia no matchea NADA

Definicion inferida del commit message y del comportamiento observado:
  1. Toma los 163 puntos de bahias_sitport
  2. Calcula ST_VoronoiPolygons (teselacion de Voronoi)
  3. Recorta contra un bbox de Chile (probablemente lat -90 a -15, lng -120 a -60
     o similar)
  4. Resta la geometria de tierra (ne_land, importada del shapefile Natural Earth
     10m que esta en geodata/ne_10m_land.*)
  5. Resultado: poligonos que cubren TODO el agua de Chile y sus alrededores,
     cada uno asignado a la bahia mas cercana

No hay evidencia de que la materialized view haya sido regenerada o REFRESH'd

3c. El recorte por costa sigue aplicandose?

El recorte por costa funciona correctamente para fiordos (Maullin no matchea
rutas por el Golfo de Ancud). Pero no limita la extension oceánica.

BLOQUE 4 — VEREDICTO
================================================================================

LA REGRESION ESTA EN EL CODIGO DEL MATCHING, NO EN LOS DATOS GEOMETRICOS.

Commit culpable: 42059c8 (mie 5 ago 14:51)
  "feat: matching geografico Voronoi+PostGIS — elimina falsos positivos en fiordos"

Linea exacta que introduce el cambio:
  sitport-routes.js (en el estado post-42059c8), funcion bahiasEnRutaPostGIS,
  la query:
    SELECT bahia_id
    FROM bahia_jurisdicciones
    WHERE ST_Intersects(geom, ST_SetSRID(ST_GeomFromGeoJSON($1), 4326))

  Esta query reemplazo el loop de distancia con cap de 80 km.

QUE SE PERDIO:
  El cap de distancia. En el sistema viejo (1a16ef5), ningun waypoint podia
  matchear una bahia cuyo punto central estuviera a mas de 80 km. En el sistema
  nuevo, la distancia es irrelevante — lo unico que importa es si la ruta
  intersecta el poligono Voronoi, y los poligonos Voronoi cubren TODO el oceano.

QUE SE GANO (y por que se hizo el cambio):
  El recorte por costa. En el sistema viejo, bahias separadas por tierra pero
  cercanas por haversine se matcheaban incorrectamente (ej: Maullin matcheaba
  rutas por el Golfo de Ancud porque la distancia haversine era <80 km aunque
  hay una peninsula de por medio). Los poligonos Voronoi recortados por costa
  resuelven este problema: la tierra actua como barrera.

EL DESAJUSTE:
  El commit resolvio un problema (falsos positivos en fiordos por distancia
  haversine que no respeta barreras de tierra) pero introdujo otro (falsos
  positivos en mar abierto por poligonos Voronoi sin cap de extension oceánica).
  Ambos problemas NO pueden resolverse con el mismo mecanismo puro:
    - Distancia pura: falla en fiordos (no ve tierra)
    - Voronoi puro: falla en mar abierto (se extiende sin limite)

NOTA: los datos geometricos (poligonos Voronoi) NO cambiaron despues de su
creacion. El problema no es que se regeneraron mas grandes — es que desde su
creacion cubren todo el oceano, y eso se hizo INTENCIONALMENTE (es la propiedad
de la teselacion de Voronoi). El estado bueno del fin de semana nunca uso estos
poligonos — usaba distancia pura.

LINEA DE CORRECCION PROBABLE (no se implementa):
  Combinar ambos mecanismos: usar los poligonos Voronoi (que respetan barreras
  de tierra) PERO agregar un cap de distancia o de area para que poligonos
  sobreextendidos no matcheen rutas lejanas. Posibles formas:
    (a) ST_Intersects + filtro ST_Distance < umbral desde el punto de la bahia
    (b) Recortar los Voronoi con un buffer maximo alrededor de cada bahia
    (c) Agregar ST_DWithin como condicion adicional a ST_Intersects
